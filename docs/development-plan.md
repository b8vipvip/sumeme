# SuMeMe 开发计划

> 最后更新：2026-07-29  
> 当前生产阶段：Phase 1 已部署，正在执行 Phase 1.5

## 1. 产品目标

SuMeMe 是一个面向个人长期记忆的多模态 AI 系统。用户可在 Android、Web、Windows 端持续发送文本、图片、音频、视频、文档和网页，系统完整保存原始内容，同时提取人物、项目、事件、偏好、关系和时间变化，并在后续对话中按相关性召回。

核心原则：

1. 原始资料与 AI 提取记忆分层保存，任何摘要都不能替代原文；
2. 所有模型能力优先调用 OpenAI-compatible 中转站；
3. LobeHub、MemPalace、Letta 等上游组件保持解耦，便于独立升级；
4. 生产操作经 GitHub Actions 和自托管 Runner 完成，不向模型开放 SSH 私钥或任意 Shell；
5. 每一阶段必须有自动测试、生产健康检查、脱敏状态快照和可回滚发布记录。

## 2. 当前架构

```text
Android PWA / Web / Windows
             │
             ▼
          LobeHub
   会话、账号、附件、同步
             │ OpenAI-compatible
             ▼
       memory-gateway
      ┌──────┴──────┐
      ▼             ▼
  MemPalace        Letta
  原文与细节       事实、人物、项目、关系
      └──────┬──────┘
             ▼
       AI 中转站模型
```

基础设施：PostgreSQL、Redis、RustFS、Qdrant、GitHub Actions、自托管 Runner、宝塔 Nginx。

## 4. Phase 1.5：可靠性和真实闭环验证

### 4.1 目标

现有健康检查只能证明容器和 HTTP 可用。本阶段要证明真实模型、双记忆和对象存储均能完成读写闭环，并避免磁盘压力导致生产事故。

### 4.2 工作项

#### A. 端到端 smoke test

- 调用 memory-gateway `/v1/models`；
- 通过 `/v1/chat/completions` 向真实中转站发送最小请求；
- 使用隔离的 `__sumeme_smoke__` 用户写入唯一测试标记；
- 轮询管理检索接口，分别确认 MemPalace 与 Letta 均返回候选记忆；
- 向 RustFS 测试桶写入、读回并删除临时对象；
- 只保存布尔结果、耗时和错误类别，不保存 API Key、对话原文或记忆原文。

#### B. 状态新鲜度

- 状态快照记录生成时间、预期刷新周期和过期阈值；
- 发布 `stale`、`age_seconds`、最后 smoke test 结果；
- 超过阈值时标记需要关注；
- 关闭的 PR/Issue 应在下一次状态采集后消失。

#### C. 磁盘保护

- 磁盘达到 80%：状态标记 warning/degraded，并运行安全清理；
- 磁盘达到 90% 或可用空间低于最低值：阻止大型拉取、构建和备份；
- 仅清理 Docker 构建缓存、悬空镜像和超出保留数量的代码发布快照；
- 永不自动执行 `docker volume prune`，永不删除 PostgreSQL、RustFS、Qdrant、Letta 数据卷；
- 清理前后记录磁盘使用量，但不输出敏感路径内容。

#### D. 自动化接入

- CI 校验 Python 脚本、Shell 脚本和 Compose；
- 生产部署前执行磁盘预检；
- 部署后自动执行基础 smoke test；
- 完整双记忆 smoke test 可配置为 `warn` 或 `required`；
- smoke test 结果进入 `.deploy/smoke/latest.json` 和 `ops-status` 快照。

### 4.3 完成标准

1. 真实中转站模型请求成功；
2. MemPalace 与 Letta 均能写入并召回隔离测试记忆；
3. RustFS 临时对象能够上传、校验并删除；
4. 状态快照可判断过期和磁盘风险；
5. 生产部署在空间不足时安全停止，不破坏已有服务；
6. CI、部署日志和状态快照不泄露密钥及用户内容。

## 5. Phase 2：完整多模态摄取

### 5.1 attachment-worker

新增独立异步 worker，不阻塞聊天主请求：

```text
LobeHub / RustFS 新附件
        ↓
任务队列
        ↓
类型识别与安全检查
        ↓
解析、转写、视觉理解
        ↓
MemPalace 原文/时间轴 + Letta 结构化事实
```

计划组件：

- Redis 队列和任务状态表；
- 附件去重、内容哈希、幂等键；
- 重试、退避、死信队列；
- 文件大小、时长、页数和成本限制；
- 中转站能力探测及模型路由。

### 5.2 文件类型

#### 图片

- OCR；
- 视觉描述；
- 人物、地点、物体、文字和事件提取；
- 原图 URL 与描述双向关联。

#### 音频

- 语音转文字；
- 说话人分段；
- 时间戳；
- 摘要、人物和事件提取。

#### 视频

- 音轨转写；
- 场景切分和关键帧；
- 时间轴描述；
- 关键人物、地点、动作、字幕和事件；
- 长视频分段与增量处理。

#### PDF / Office

- 原生文本、表格和元数据；
- 页面渲染与视觉理解；
- 扫描件 OCR；
- 页码级引用；
- PPT、Word、Excel 的结构化解析。

### 5.3 历史补录

- 扫描 LobeHub 数据库与 RustFS；
- 对历史附件建立任务；
- 可暂停、继续和限速；
- 处理进度可查询；
- 失败任务可重试。

### 5.4 完成标准

- 每种文件至少有一套端到端测试样本；
- 可从记忆结果追溯到原始文件和具体页码/时间点；
- 重复上传不重复消耗模型；
- worker 故障不影响正常聊天；
- 处理成本、失败原因和进度可观察。

## 6. Phase 3：记忆管理 UI

### 6.1 功能

- 全局搜索原文和结构化记忆；
- 按人物、项目、主题、时间、来源和文件类型筛选；
- 查看 MemPalace 原文与 Letta 事实的关联；
- 修改、确认、合并、删除错误记忆；
- 标记“不要记住”“敏感”“仅本次会话”；
- 设置保留期限；
- 时间线、人物页、项目页和关系图；
- 数据导出和彻底删除。

### 6.2 数据治理

- 每次修改保留审计记录；
- 软删除与可配置彻底删除；
- 记忆来源和置信度；
- 冲突记忆并列展示，不静默覆盖；
- 删除原文件时处理派生文本、向量和结构化事实。

## 7. Phase 4：Android、Web 和 Windows 产品化

- PWA/TWA；
- 系统“分享到 SuMeMe”；

### Web

- 记忆引用；
- 管理 UI；

## 8. Phase 5：多用户、安全与运维

- LobeHub 用户 ID 传递到 memory-gateway；
- 每用户独立 MemPalace wing、Letta Agent 和对象权限；
- 用户配额、限速和成本统计；
- OAuth、会话和管理权限；
- 审计日志；
- 备份恢复演练；
- 安全扫描与依赖固定版本；
- 灾难恢复目标（RPO/RTO）；
- 监控、告警和容量预测。

## 9. 发布策略

每个阶段采用以下流程：

```text
开发分支
→ 单元测试 / 静态检查
→ Pull Request
→ GitHub-hosted CI
→ 合并 main
→ VPS Runner 自动部署
→ 健康检查 + smoke test
→ 更新 ops-status
→ 验证线上 SHA
```

回滚规则：

- 应用代码可自动恢复上一份发布快照；
- 数据库迁移必须提供向前修复或明确的反向迁移；
- 涉及数据结构变化前必须先备份；
- 未通过 smoke test 的版本不得标记为稳定。
